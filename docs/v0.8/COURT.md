# V0.8.2 王庭构图验收

[48 张同尺寸前后截图](https://suducat.github.io/shadow-king/review/court/) · [祭典开启](https://suducat.github.io/shadow-king/review/court/open.webp) · [占领与回应](https://suducat.github.io/shadow-king/review/court/occupied.webp)

基线是正式版提交 `c25ca24`。在改动之前和之后，使用浏览器打开正式构建，从主页进入模式选择，切到祭典，选择全知者，确认布阵并进入第一回合。分别在 1440×900、1280×720、390×844、844×390 拍摄这六个状态，每组的视口、低画质和减少动态效果设置一致。对照页按需加载原尺寸无损 WebP，均逐像素核对过浏览器 PNG。

## 从截图发现并修正的地方

| 观察 | 实现 |
| --- | --- |
| 桌面模式选择只占左半屏，右侧场景被隐藏 | 左侧保留规则和对战方式的连续选择。右侧固定展示尺寸，用蒙面棋子与王冠、三枚符印与祭台分别解释经典和祭典。预留两行说明空间，切换后标题和按钮保持原位。 |
| 主页的规则摘要、章节文字和棋盘争夺注意力 | 以王和蒙面棋子组成单幅王庭插画，保留标题、一句文案、开始和快速规则。声音、设置与制作信息仍可从页眉打开。 |
| 手机上 AI 长卡片将挑战说明和开始键推到首屏下方 | 使用紧凑的五档列表，当前对手的徽章轮廓、光色、难度、适合人群和规则集中展示。全知者显示权限告知及专用开始键。 |
| 对局侧栏与三维渲染区域分开定位，形成硬边与遮挡 | 布阵与对局共用固定棋盘区域，桌面侧缘渐入统一底色，Canvas 保持无蒙版。回合与行动方在同一栏，规则与公开战报改为抽屉。手机横屏将两组操作移至左侧。 |
| 第一次横屏检查发现确认布阵键与镜头工具拥挤 | 为横屏控制区预留宽度，拆开状态和操作行。四个尺寸均检验实际触点、开局按钮和棋盘四角。 |

## 回归验证

- `npm test` 通过 142 项。正式构建通过 TypeScript 与 Vite，保留相对资源路径。
- `npm run build:test` 后运行 `npm run test:court:browser`。四种尺寸分别验证规则切换、全知者告知、换对手、交换两枚棋子、确认布阵、抽屉键盘焦点、落子及真实 Worker 回应。四角格面与角色顶部投影均位于棋盘内且可命中。
- `node tests/ritual-browser.cjs` 通过十组流程。从最后一名死士被吃开始，实测王公开、占领、对方完整回应和祭典结算，以及回应期间弑王、双目标斩杀、切回经典等分支。
- `node tests/combat-production.cjs` 在正式构建实走八步，蓝方弑王结算，包含跳过动作与终局演出。
- `node tests/rendering-browser.cjs` 在 DPR 2 下验证棋子选择、移动与交接。1440×900、1440×700、390×844 的中档缓冲分别为 1740×1360、1228×960、780×1208。在每个场景中，选中和移动都没有增加缓冲重分配次数。
- 截图来自 Linux Chromium 156 / SwiftShader，模拟鼠标及手机触控。本轮没有物理手机、Safari 或 Mac 原生 GPU 测量，也没有据此估算硬件帧率。

两幅菜单插画随游戏本地分发，合计 336,954 字节。来源见仓库素材声明。对局继续使用现有 3D 棋子与规则。独立截图页的图片只在查看对照时请求。
